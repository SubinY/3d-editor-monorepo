# 拾取系统优化：彻底解决 TransformControls 误选问题

## 问题背景

用户报告在某些情况下会触发警告：
```
Cannot attach TransformControls to itself or its children
```

这说明在点击场景时，拾取系统返回了 TransformControls 的子对象，导致尝试将 TransformControls 附加到自己的子对象上。

## 根本原因分析

### TransformControls 的内部结构

TransformControls 的层级结构如下：
```
TransformControls (root)
├─ TransformControlsPlane
└─ TransformControlsGizmo
   ├─ Mesh (X轴箭头)
   ├─ Mesh (Y轴箭头)
   ├─ Mesh (Z轴箭头)
   ├─ Mesh (旋转圆环)
   └─ ... (其他交互部件，都是 Mesh 类型)
```

### 问题所在

之前的 `SelectionManager.isSelectable()` 方法只检查对象自身的类型，没有完整遍历父级链。当用户点击到 TransformControlsGizmo 下的某个 Mesh 时：

1. **对象类型检查通过**：该对象的 `type` 确实是 `'Mesh'`
2. **父级检查不完整**：只检查了直接父级，没有递归检查整个祖先链
3. **被误判为可选**：系统认为这是一个普通的 Mesh，允许选中
4. **触发警告**：尝试将 TransformControls 附加到这个 Mesh 上，触发内部检查警告

## 解决方案

### 核心原则：完整的父级链遍历

在 `SelectionManager.isSelectable()` 方法中，必须**向上遍历整个父级链**，确保对象及其所有祖先都不是辅助对象或控制器。

### 实现细节

```typescript
private isSelectable(object: THREE.Object3D): boolean {
  // 定义所有不可选的类型
  const nonSelectableTypes = new Set([
    'AxesHelper',
    'GridHelper',
    'TransformControls',
    'TransformControlsPlane',
    'TransformControlsGizmo',
    'BoxHelper',
    'ArrowHelper',
    'Line',
    'LineSegments',
    'LineSegments2',
    'Sprite',
    'Scene'
  ])
  
  // 向上遍历整个父级链
  let current: THREE.Object3D | null = object
  while (current) {
    // 检查类型
    if (nonSelectableTypes.has(current.type)) return false
    
    // 检查名称（用于特殊标记）
    if (current.name.startsWith('__')) return false
    
    // 检查 userData 标记
    if (current.userData?.nonSelectable) return false
    
    current = current.parent
  }
  
  // 只允许选择 Mesh 类型的对象
  return object.type === 'Mesh'
}
```

### 关键改进

1. **完整的父级链遍历**：使用 `while` 循环遍历所有祖先，直到 `parent` 为 `null`
2. **多重检查**：检查类型、名称和 userData，三重防护
3. **命名约定**：使用 `__` 前缀标记内部对象（如多选临时分组 `__multiSelectionGroup__`）
4. **类型白名单**：最终只允许 `Mesh` 类型通过

### 简化外部逻辑

由于 `pick()` 方法已经在内部完整过滤，外部调用方（如 `Editor.vue` 的 `handlePointerDown`）可以简化逻辑：

```typescript
const result = ctx.value.selection.pick(...)

if (!result.object) {
  // pick() 返回 null，说明点击到不可选对象或空白处
  // 取消选择
} else {
  // pick() 返回了对象，说明这个对象一定是可选的
  // 执行选择逻辑
}
```

不再需要手动检查 `result.object.type === 'GridHelper'` 等条件。

## 防护层级

### 第一层：SelectionManager.pick()
- 使用 `isSelectable()` 过滤所有射线相交结果
- 只返回真正可选的对象
- 返回 `null` 表示未命中可选对象

### 第二层：TransformController.attach()
- 内部仍保留 `isChildOfControls()` 检查
- 作为最后一道防线，防止意外情况
- 记录警告但不会崩溃

### 第三层：命名约定和标记
- 使用 `__` 前缀标记内部对象
- 设置 `userData.nonSelectable = true` 标记
- 禁用辅助对象的 `raycast` 方法

## 设计原则总结

### 1. 完整性原则
- 遍历完整的父级链，不遗漏任何祖先
- 多维度检查（类型、名称、标记），不遗漏任何情况

### 2. 职责分离原则
- 过滤逻辑在 `SelectionManager` 内部完成
- 外部调用方信任 `pick()` 的返回结果
- 避免逻辑重复和不一致

### 3. 防御性编程原则
- 多层防护（pick 过滤 + attach 检查 + 命名约定）
- 即使前面的检查失败，后面的防线也能捕获
- 记录警告而不是崩溃

### 4. 可维护性原则
- 集中管理不可选类型的列表
- 使用清晰的命名约定（`__` 前缀）
- 详细的注释和文档
