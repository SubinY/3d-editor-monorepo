# 电柜设备运维 3D 编辑器 v1 需求文档（资产编辑器 / 场景编辑器）

- 文档版本：v1.0（草案）
- 编制日期：2026-02-26
- 适用范围：`apps/demo-view`（业务应用）+ `packages/engine`（编辑内核能力扩展）
- 前置版本状态：v0.1～v0.4 已完成；v0.5（碰撞检测）待开发（纳入 v1.1 交付）

## 0. 背景与目标

### 0.1 业务背景

电柜设备运维场景中，资产具有“非标多、复用强、需要拆解查看细节”的特点。v0.x 已打通资产/场景的编辑闭环，但资产编辑仍偏“占位拼装”，缺少可落地的“模型导入、可验证装配、可钻取查看、可复用组件库”的产品能力。

### 0.2 v1 目标（面向可交付）

1. 资产编辑器支持导入 `glTF/GLB`，并将其转化为可复用的 3D 模型资产/元器件（导入过程支持可配置的数据清洗与轻量处理）。
2. 资产编辑过程提供可控的碰撞检测校验能力（“检测 + 反馈”闭环；不做强约束与自动修正）。
3. 资产编辑器与场景编辑器均支持“按配置开关的 Mesh 点击放大/钻取”，用于查看复杂模型细节。
4. 资产编辑器补齐“组件化资产”的最小能力：组件库、元数据、可复用导入结果、碰撞校验提示，支撑可持续搭建与复用。

补充：v1 仅做**资产 -> 场景**链路，不做“场景拼装场景（scene -> scene）”。

### 0.3 v1 非目标（明确不做）

- PLC 实时数据、告警联动、诊断高亮逻辑（可保留扩展点）。
- 权限体系、多人协作、云同步（本地优先，后续可演进）。
- 复杂布线、线缆路径规划、回路计算（v1 仅做元器件与柜体装配，必要时做“占位/接口预留”）。
- 复杂装配结构适配（柜体模板、锚点/插槽、装配约束求解、自动布置等）。
- 离线导出资产包/场景包（v1 不需要导出能力）。

### 0.4 已确认决策（用于进入开发）

1. 导入后的主格式：**保留 GLB 作为源资产**（只在业务层保存引用与覆盖配置，不把几何转成超大 JSON）。
2. v1 不做导出（资产包/场景包/BOM 导出均不在 v1 范围）。
3. 碰撞校验策略：**仅提示**（不阻止放置/保存，不做自动修正）。
4. 钻取：在资产编辑器与场景编辑器均可用，且为**只读查看**（不进入资产内部编辑）。

## 1. 术语与边界

### 1.1 术语

- 资产（Asset）：可复用的电柜/元器件/子装配，进入资产库管理，可被场景引用实例化。
- 场景（Scene）：现场布局，引用多个资产实例进行摆放与保存。
- 组件（Component / Part）：用于装配的元器件或结构件（断路器、接触器、导轨、背板、柜门等）。
- 钻取（Drill）：从整体对象进入子 Mesh/子节点层级，进行聚焦、隔离与细节查看。
- 轻量处理（Light Processing）：导入后对模型做“体积/性能友好”的处理（可选项、可回滚）。

### 1.2 分层边界（沿用 v0.x 结论）

- `packages/engine`：3D 编辑运行时能力（选择、变换、历史、序列化、插件机制、基础工具能力）。
- `apps/demo-view`：资产库与业务流程（资产文件管理、导入向导、碰撞校验配置、UI/交互、数据持久化）。

### 1.3 对象模型（v1 范围）

- 组件（Component）-> 用于拼装资产的最小复用单元，可由 GLB 导入生成。
- 资产（Asset）-> 由多个组件拼装而成，可被场景实例化。
- 场景（Scene）-> 由多个资产实例组成的布局结果。
- 非范围：场景嵌套场景（scene -> scene）与场景模板复用体系。

## 2. 用户角色与关键流程

### 2.1 用户角色

- 建模/工艺工程师：导入模型、配置组件属性、装配并生成资产模板。
- 运维/交付人员：在场景中放置资产，钻取查看结构细节，检查安装空间。
- 管理员（可选）：维护组件库分类、版本与规范。

### 2.2 关键流程（v1 必须跑通）

1. 导入 `GLB`（元器件）→ 预览/轻量处理 → 入库为组件 → 在资产编辑器拼装成电柜资产 → 碰撞校验（仅提示）→ 保存 → 场景实例化摆放 → 钻取只读查看细节。

## 3. 数据与存储（v1 必须升级点）

### 3.1 现状问题

当前 `apps/demo-view/src/stores/*` 使用 `localStorage` 持久化 `SceneSchema`。当引入真实 `glTF/GLB` 时：

- `SceneSchema.objects[].geometry.attributes` 若直接序列化为数组，会导致 JSON 体积巨大，超出 `localStorage` 上限且加载慢。
- 模型二进制、纹理等需要“二进制存储 + 引用”的机制。

### 3.2 v1 存储策略（建议作为 v1 前置工作）

- 资产/场景元数据：可继续保留在 `localStorage`（快速列表与检索），并增加对 v1 的字段扩展。
- 模型源资产：以 **GLB** 形式存入 IndexedDB（`Blob/ArrayBuffer`），并在资产/对象的 `userData` 中保存 `resourceId` 引用。
- 兼容性：保留对 v0.x（纯 `SceneSchema`）资产的读取；对 v1 新增 `storageVersion = 1` 标识用于区分与迁移。

建议的最小落地结构（仅用于指导实现，不强制内核参与）：

- `AssetRecord`（资产元数据，localStorage）：`id/name/createdAt/updatedAt/storageVersion/sourceResourceId?/sceneData`
- `ResourceRecord`（二进制资源，IndexedDB）：`resourceId/blob/mime/size/hash?/createdAt`

其中：

- `sourceResourceId` 指向 GLB 的 `resourceId`。
- `sceneData` 仍沿用 `SceneSchema`，但仅保存“场景结构 + 覆盖配置”，不直接内联巨大顶点数组。

### 3.3 数据结构（建议扩展方向）

为支持导入/钻取/装配校验，建议在 `ObjectSchema.userData` 或 `SceneSchema.customData` 承载以下信息（不强绑内核，业务层解释）：

- `source`: `{ type: 'gltf', resourceId, uri?, nodePath?, meshIndex? }`
- `focus`: `{ enabled: boolean, mode: 'camera' | 'drill', keepHierarchy?: boolean }`
- `collision`: `{ enabled: boolean, group: string, hull?: 'aabb' | 'obb' | 'mesh', margin?: number }`
- `part`: `{ sku?, brand?, spec?, size?: [w,h,d], tags?: string[] }`

## 4. 功能需求 v1（按优先级拆解）

> 标注：P0 必须；P1 应该；P2 可选。

### 4.1 需求 1：glTF/GLB 导入并转化为可复用模型（P0）

#### 4.1.1 导入范围

- 支持格式：`.glb`（P0）；`.gltf`（P1，目录形式需连带 `.bin` 与 `textures/*`）。
- 导入入口：
  - 资产库：导入为“组件”（元器件/结构件）并入库。
  - 资产编辑器：将导入模型直接加入当前资产（并可选择“同时入库为组件”）。

#### 4.1.2 导入向导（必备交互）

- Step 1：选择文件（支持多选批量导入，批量时走同一套默认策略）。
- Step 2：预览与基础信息
  - 模型层级/节点数、三角面数、材质/贴图数量、包围盒尺寸、单位/轴向推断结果。
- Step 3：处理策略（可选项需可回退）
  - 坐标系处理：`Y-up/Z-up` 选择；导入后统一到引擎坐标系。
  - 单位与缩放：支持 `mm/cm/m` 选择，支持“自动缩放到目标真实尺寸”。
  - 层级策略：`保留层级` / `扁平化（合并为更少节点）`。
  - 材质策略：统一为 PBR（`MeshStandardMaterial`），支持“合并相同材质”。
  - 纹理策略：保留原图（默认）/ 降采样（P1，需明确会损失质量）/ 不导入贴图（仅颜色占位，P2）。
  - 网格策略：保留原网格（默认）/ 合并静态网格（P1）/ 生成简化 LOD（P2）。
  - 清理策略（P0）：删除空节点、删除未引用材质/纹理、修正缺失法线（必要时重算）、可选“应用变换到顶点”（apply transforms）。
- Step 4：结果报告与落库
  - 展示“处理前后对比”：节点数、三角面数、资源大小、预计加载耗时（粗略估算即可）。
  - 生成缩略图（资产卡片使用），失败可重试。
  - 统一归档：导入输入为 `.gltf` 时，导入过程将其打包/转换为 `.glb` 再入库（对业务侧透明）。
  - 入库：生成组件记录（名称、分类、标签、`resourceId(GLB)`、尺寸、统计信息、导入策略快照）。

#### 4.1.3 轻量处理的工程要求

- 性能：导入与处理不得阻塞主线程；重操作在 Web Worker 中执行（P0）。
- 可追溯：每个入库模型记录 `importProfile`（策略快照），便于复现与回滚（P0）。
- 可控：默认策略以“保真 + 可用”为主，激进压缩/简化放到可选项（P0）。
  - v1 默认策略：不做贴图降采样、不做网格简化、不做自动合并网格（仅做安全清理）。

#### 4.1.4 验收标准（P0）

- 导入 1 个 5–20MB 的 GLB：
  - 3 秒内完成预览渲染（以开发机为准，可配置阈值）。
  - 入库后在资产库显示缩略图、尺寸信息、三角面数等统计。
  - 拖入资产编辑器/场景编辑器可实例化，保存后刷新页面仍能加载（GLB 二进制从 IndexedDB 读取）。
- 导入失败要有可理解的报错（文件损坏、纹理缺失、跨域资源等）。

### 4.2 需求 2：资产编辑的碰撞校验（P0）

> 目标：不是做完整物理仿真，也不做复杂装配约束。v1 只做“相交碰撞校验 + 提示”，降低拼装错误概率。

#### 4.2.1 碰撞检测分级（v1 最小实现）

- Level 0（P0）：AABB 包围盒相交检测（快速、可覆盖大部分错误）。
- Level 1（P1）：OBB / 近似 Hull（如后续误报较多再引入）。

#### 4.2.2 检测触发时机（P0）

- 变换交互中（拖拽/旋转/缩放）：节流检测（例如 60–120ms 一次），只做 Level 0。
- 变换结束（mouse up / commit）：做一次全量检测（Level 0），并输出冲突列表。
- 保存资产前：执行一次全量检测（Level 0），若有冲突则给出提示，但不阻止保存。

#### 4.2.4 反馈与交互（P0）

- 视觉反馈：
  - 碰撞对象描边/高亮（可复用现有 outline/高亮机制）。
- 信息反馈：
  - 右侧面板显示“问题列表”：对象 A ↔ 对象 B，问题类型（碰撞），定位按钮（点击聚焦）。
- 约束策略：仅提示（P0）。

#### 4.2.5 引擎/插件接口建议（实现层）

为保持分层边界清晰，建议内核/扩展提供纯能力接口，业务侧决定 UI：

- `collision.check(objects, options) -> CollisionResult[]`
- `collision.subscribe(event, handler)`：在 transform commit 时发事件（或业务主动调用）。
- 支持 collision layer/mask 或 group 过滤，避免无意义的全量检测。

#### 4.2.6 验收标准（P0）

- 资产编辑器中拖拽元器件到柜体：
  - 明显穿插能被检测到，并在 UI 给出对象定位与说明。
  - 100 个元器件场景下拖拽仍可用（卡顿可接受但不能“明显掉帧到不可操作”）。

### 4.3 需求 3：Mesh 点击放大/钻取（资产编辑器 + 场景编辑器）（P0）

#### 4.3.1 设计目标

- 用“配置开关”控制哪些模型/哪些 Mesh 可钻取，避免所有 Mesh 都可钻取导致交互混乱。
- 钻取既要满足“快速聚焦看细节”，也要支持“进入层级查看/隔离组件”。

#### 4.3.2 配置方式（P0）

- 模型级开关：组件/资产可设置 `focus.enabled = true/false`，默认关闭。
- Mesh 级开关：节点 `userData.focus.enabled` 支持覆盖；可在资产编辑器中批量勾选（P1）。
- 交互模式开关：
  - `cameraFocus`：点击后仅做相机飞行到包围盒（简单、通用，P0）。
  - `drillDown`：点击后进入“钻取态”，允许继续点选子节点、隔离显示、面包屑返回（P0）。

#### 4.3.3 交互细节（P0）

- 点击可钻取 Mesh：
  - 相机平滑飞行到“适配视图（fit to box）”并自动调整 target。
  - 进入钻取态后，支持“仅显示当前分支”或“其他透明淡化”（二选一，建议淡化默认）。
  - 提供面包屑：`资产实例 / 子组件 / Mesh`，支持一键返回上一级与退出钻取。
  - 钻取态为只读查看：禁用变换 gizmo 与编辑动作，仅允许相机导航、选择与信息查看；退出钻取态恢复编辑。
- 输入规则建议：
  - 单击：选择
  - 双击或 `Alt + 单击`：钻取（避免与当前选中冲突）
  - `Esc`：退出钻取态

#### 4.3.4 场景编辑器中的钻取（P0）

场景中资产通常是“实例”，钻取要避免破坏实例编辑逻辑：

- 钻取仅影响视图与选择，不改写资产数据。
- 钻取为只读：场景编辑器中不允许对钻取到的子部件做移动/旋转/缩放等编辑；如需编辑，走“跳转资产编辑器”流程。

#### 4.3.5 验收标准（P0）

- 通过属性开关，能指定某些 Mesh 可钻取，其他 Mesh 只可选中。
- 钻取过程中相机动画流畅、可回退；不会导致编辑器状态错乱（例如 gizmo 丢失、选中错乱）。

### 4.4 需求 4：资产编辑器可用性增强（不做复杂装配结构）（P0/P1）

> 目标：在不引入柜体模板/锚点/装配约束求解的前提下，让“导入 + 组件库 + 拼装 + 碰撞提示”形成可持续使用的工作流。

#### 4.4.1 组件库体系（P0）

- 组件分类（建议最小集合）：
  - 柜体/结构：柜体、背板、门、导轨、线槽
  - 电气元器件：断路器、接触器、继电器、电源、端子排、PLC 模块（占位也可）
  - 附件：螺丝、支架、铭牌（可后置）
- 组件元数据（P0）：
  - 尺寸（W/H/D）、安装方式（DIN 导轨 / 背板螺丝 / 门板）、推荐间距、关键标签（品牌/型号/电气参数可后置）
  - 碰撞配置：默认 hull（AABB/OBB）、margin、collision group
- 组件预览与可用性（P0）：
  - 缩略图、尺寸与名称可见
  - 拖拽放置时显示“放置预览幽灵体”

#### 4.4.2 关键编辑能力补齐（P1，建议纳入 v1）

- 多选与批量编辑：对齐、等距分布、阵列复制（例如端子排/模块重复）。
- 结构化分组：子装配（如“左侧模块组”）一键折叠/隐藏/锁定。
- 替换组件：用新型号替换旧型号（最小实现：替换几何与元数据，保留 transform）。

#### 4.4.3 验收标准（P0）

- 能使用“组件库”完成一套电柜资产拼装，并能保存/加载。
- 碰撞问题可被提示并定位（高亮 + 问题列表 + 一键聚焦）。

## 6. 基于当前目录结构的开发任务映射

### 6.1 `apps/demo-view`（业务实现主战场）

- `src/router/index.ts`
  - 保持 `asset-library -> asset-editor -> scene-editor` 主流程清晰。
  - 钻取只读态相关 query/state 路由参数（如需）在此统一约定。
- `src/stores/asset-store.ts`
  - 扩展 `AssetRecord`：`storageVersion/sourceResourceId/importProfile` 等字段。
  - 兼容读取 v0.x 旧记录。
- `src/stores/scene-store.ts`
  - 场景记录引用资产实例时保留 `assetId` 与必要覆盖信息。
- `src/views/asset-library/AssetLibrary.vue`
  - 导入入口（组件导入/资产导入）、列表筛选、导入结果反馈。
- `src/views/asset-editor/*`
  - 导入向导、组件库拖拽拼装、碰撞提示面板、保存资产。
  - 钻取只读态交互（进入/退出、面包屑、相机聚焦）。
- `src/views/scene-editor/*`
  - 从资产库实例化资产、场景摆放、场景内钻取只读查看。
- `src/views/asset-viewer/*` + `src/views/scene-viewer/*`
  - 与编辑器一致的只读钻取体验（不含编辑动作）。
- `src/assets/mounted_motor_electrical_component/*`
  - 作为首批导入回归样本，验证 `.gltf` 入库转 `.glb` 流程。

### 6.2 `packages/engine`（能力补齐）

- 碰撞检测最小能力：
  - 提供批量 `AABB` 检测 API 与结果结构。
  - 在 transform 交互 commit 时可触发事件或供业务主动调用。
- 钻取只读能力：
  - 提供稳定的对象拾取、包围盒计算、相机 `fit-to-box` 基础能力。
  - 不在内核侧引入业务耦合规则（如资产库/导入策略）。

### 6.3 v1 不在当前目录结构内展开的事项

- 场景模板系统（scene -> scene）
- 复杂装配约束（锚点/插槽/自动布置）
- 导出链路（资产包/场景包/BOM）

## 7. 里程碑建议（按风险拆分交付）

> v1 建议拆成小步快跑，降低“导入 + 存储 + 交互”耦合风险。

- v1.0：glTF/GLB 导入向导 + IndexedDB 存储与引用 + 组件入库 + 基础拖拽实例化
- v1.1：碰撞检测 Level 0 + 问题列表面板 + 保存前碰撞校验（仅提示）
- v1.2：Mesh 点击放大/钻取（含配置开关、面包屑、退出机制；只读）
- v1.3：组件库体验增强（分类/搜索/标签/替换）+ 批量编辑能力补齐（对齐/阵列）

## 8. 开发约束与验收总纲（便于直接开工）

- 性能基线：单个 GLB（5–20MB）导入预览可用；场景中 10–20 个资产实例可流畅编辑（后续再做大场景优化）。
- 可靠性：IndexedDB 资源缺失/损坏要有降级提示，不允许白屏；asset/scene 元数据与 resource 引用需可自检（至少能提示“资源缺失，请重新导入”）。
- 兼容性：v0.x 的本地资产/场景仍可打开；v1 的资产标识 `storageVersion = 1`。
