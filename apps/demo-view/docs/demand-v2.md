# 电柜设备运维 3D 编辑器 v2 需求文档（可进入开发）

- 文档版本：v2.0（重梳理，可直接拆任务开发）
- 编写日期：2026-02-26
- 适用范围：`apps/demo-view`（业务应用）+ `packages/engine`（编辑内核，按需补齐能力）
- v2 核心目标：围绕“资产导入 → 资产库 → 资产编辑 → 场景实例化 → 查看”打磨可交付体验，补齐导入元数据、钻取只读体验、碰撞提示闭环与组件化基础。

## 0. 已确认约束（必须遵守）

- 资源主格式：保留 `GLB` 作为源资源（存 IndexedDB），不把几何/纹理转成超大 JSON buffer 常驻在业务数据里。
- 不需要导出能力：不做资产包/场景包/BOM 等导出。
- 碰撞校验：只提示，不阻止摆放/保存，不自动修复。
- 钻取：只读查看；进入钻取后必须能“一键复原”。
- 链路范围：仅 `资产 -> 场景`，不做 `scene -> scene` 模板拼装。
- 创建资产前置：**新建资产必须先选择一个机柜**（用于确定 2D 安装板尺寸与 2D→3D 映射坐标系）。
- 2D/派生范围：仅在**资产编辑器**提供“2D 排布 + 3D 派生预览”；**场景编辑器只做 3D 场景编辑**（实例化资产并摆放）。

## 1. 名词与对象模型

- 资源（Resource）：二进制或文件类数据，如 `GLB`、缩略图、（可选）原始 `gltf bundle` 包。
- 组件（Component）：可复用的最小单元，通常对应“一个可摆放的元器件/结构件”，背后引用一个 `Resource(GLB)`。
- 机柜（Cabinet）：一种“基座组件/基座资产”，提供安装板（2D 面板）尺寸、原点与朝向；创建资产时必须先选定。
- 资产（Asset）：多个组件的组合（电柜/柜门/背板+元器件组合），可被场景实例化。
- 场景（Scene）：多个资产实例的摆放与保存。
- 2D 安装板（Panel2D / Layout2D）：资产编辑器中的 2D 排布平面（单位 mm），元器件在其上进行位置/旋转/对齐排布。
- 3D 派生（Derived3D）：由 `Layout2D + 机柜映射规则` 自动生成的 3D 摆放结果（资产编辑器用于预览；场景编辑器用于实例化显示）。
- 钻取（Drill / Focus）：从整体进入某个 mesh/节点的只读聚焦查看（隔离、淡化、相机聚焦、可退出复原）。

## 2. 业界导入方式与本项目选择

- glTF 在业界通常有两种交付形态：
- 单文件：`.glb`（推荐给终端用户导入，依赖最少，最稳定）。
- 多文件：`.gltf + .bin + textures/*`（常见于 DCC/工具链导出，引用外部文件，适合版本管理与增量替换）。
- Web 产品常见导入 UX：
- 直接导入 `.glb` 文件。
- 导入 `.zip`（里面包含 `.gltf` 与引用资源），解压后做依赖校验再导入。
- 导入文件夹（浏览器能力受限，通常依赖 `webkitdirectory` 或拖拽目录）。
- 本项目 v2 策略：
- P0：继续支持 `.glb`；继续支持 `.gltf bundle` 的“多文件同时选择导入”（与你当前资产文件夹形态一致）。
- P1：补齐 `.zip` 导入与“选择文件夹导入”的 UX（更贴近业界）。

## 3. v2 需求范围（P0/P1）

### 3.1 资产导入与轻量处理（P0）

#### 3.1.1 支持的输入

- 输入 A：单个 `.glb` 文件。
- 输入 B：`gltf bundle`（用户一次性选择多文件，至少包含一个 `.gltf`；其余为 `.bin`、贴图等被引用资源）。

#### 3.1.2 导入处理规则（轻量，不做“复杂清洗”）

- 解析：能正确解析 `.gltf` 对外部资源的引用路径（相对路径）。
- 归一化：导入后统一产出一个 `.glb`（作为后续加载/渲染/复用的唯一来源）。
- 清理：删除空节点、移除无几何贡献的占位节点（不做网格合并、不做材质合并、不做重拓扑）。
- 统计：导入完成必须得到并持久化以下指标：
- 名称：默认取文件名，可在资产库改名。
- 尺寸：模型整体包围盒 `W/H/D`（单位统一为 `m`，UI 可同时显示 `mm`）。
- 三角面数：tris（以最终导出的 `.glb` 为准）。
- 附加统计（可选）：节点数、mesh 数、材质数、纹理数、glb 字节大小。

#### 3.1.3 存储与引用

- 导入产物：`.glb` 存入 IndexedDB（`src/stores/resource-store.ts`）。
- 元数据：资产记录存 localStorage（`src/stores/asset-store.ts`），必须包含 `sourceResourceId`、`thumbnailResourceId`、`stats`。
- 不允许：把 `THREE.BufferGeometry` 的 attribute 数据序列化进资产/场景 schema。

#### 3.1.4 缩略图（P0）

- 导入完成自动生成缩略图（建议 webp，失败回退 png）。
- 缩略图资源同样存 IndexedDB，并记录到资产元数据中。

#### 3.1.5 错误与提示（P0）

- gltf bundle 缺资源：必须明确提示缺失的文件名列表，并允许用户重新选择补齐后重试。
- 纹理加载失败：导入仍可完成，但必须给出“可能纹理丢失”的告警提示。

### 3.2 资产库信息展示与管理（P0）

- 资产卡片必须可见：
- 缩略图。
- 名称。
- 尺寸（W×H×D）。
- 三角面统计（tris）。
- 列表能力（P0）：搜索（按名称）、排序（最近导入、tris、尺寸）。
- 基础管理（P0）：重命名、删除（删除需同时删除资源引用或做引用计数，P0 可先做“仅删除记录并提示资源残留”）。
- 入口不变：`src/views/asset-library/AssetLibrary.vue`。

### 3.3 钻取只读体验（P0）

#### 3.3.1 配置开关语义（必须解释清楚）

- 每个对象（asset editor 的组件实例、scene editor 的资产实例、以及导入模型的 mesh）都有 `focusEnabled`（允许钻取）属性。
- UI 文案统一：`允许钻取（Alt+双击进入，Esc 退出）`，并提供一行帮助说明“钻取仅用于只读查看细节，不会进入编辑”。

#### 3.3.2 进入钻取（P0）

- 触发：`Alt + 双击` 命中且 `focusEnabled=true` 的对象/mesh。
- 行为：
- 相机聚焦到目标包围盒（fit-to-box）。
- 其他对象淡化或隐藏（默认淡化，保持空间参照）。
- 禁用变换控件与编辑操作（只读）。
- 顶部或状态栏显示“已进入钻取：目标名称”，并提供“退出钻取”按钮。

#### 3.3.3 退出与复原（P0，必须通过验收）

- 退出方式：`Esc`、点击“退出钻取”按钮。
- 复原内容：
- 恢复进入钻取前的相机位置与目标（至少恢复到进入前视角，不允许卡死在目标上）。
- 恢复淡化前的材质/透明度状态（不应出现“退出后仍是半透明”的残留）。
- 恢复进入钻取前的选中对象（或回到进入钻取时的父对象）。

#### 3.3.4 失败反馈（P0）

- 用户在未开启 `focusEnabled` 的对象上尝试钻取：给出一次性提示“该对象未开启钻取（可在右侧面板开启）”。

#### 3.3.5 适用页面（P0）

- 资产编辑器：`src/views/asset-editor/*`
- 场景编辑器：`src/views/scene-editor/*`
- 只读查看器：`src/views/asset-viewer/*` 与 `src/views/scene-viewer/*`（交互保持一致但不提供编辑能力）

### 3.4 碰撞检测与提示闭环（P0）

#### 3.4.1 检测目标与粒度

- P0 粒度：组件实例之间做 AABB（包围盒）相交检测（先做粗略，保证实时与可解释）。
- P1 粒度：可选支持 mesh 级别或 OBB（更精确但更重）。

#### 3.4.2 触发时机（P0）

- 组件被移动、旋转、缩放后的“提交时刻”触发（拖拽过程中可节流）。
- 手动触发入口：右侧面板提供“重新检测”按钮。

#### 3.4.3 提示呈现（P0）

- 视口中高亮碰撞对象（红色描边或发光，不改变永久材质）。
- 右侧面板提供“碰撞列表”：
- 每条显示：对象 A 名称、对象 B 名称、时间戳或排序。
- 操作按钮：`定位 A`、`定位 B`（选中并镜头聚焦）。
- 规则：只提示，不阻止保存；保存时可提示“存在 N 处碰撞”。

#### 3.4.4 可配置忽略（P1）

- 对象级：`collisionEnabled` 开关。
- 分组级：`collisionGroup`（相同组不互检或按规则互检）。

### 3.5 资产编辑器的“可用拼装”最低增强（P0）

> v2 不做复杂装配结构适配（插槽/约束求解等），只保证“组件能摆放、能复用、能校验碰撞、能钻取查看细节”。

#### 3.5.1 新建资产必须先选机柜（P0）

- 新建资产流程（入口在资产库）：`选择机柜（必选） -> 进入资产编辑器`。
- 机柜来源：来自“组件库”的一类组件（`ComponentRecord.kind = 'cabinet'` 或等价字段），导入方式同普通组件（`GLB` 入库）。
- 安装板尺寸来源（P0 取可落地方案）：
- 优先：在机柜组件元数据中手动配置 `panel`（宽/高/mm、原点、朝向、厚度/离地等）。
- 退化：仅用机柜整体包围盒推导“可用安装板尺寸”（只用于 P0 验收 Demo，不建议用于真实工程）。
- 未选择机柜的行为：不允许进入资产编辑器；提示“请先选择机柜以确定安装板尺寸”。

#### 3.5.2 资产编辑器 2D 排布 + 3D 派生预览（P0）

- 资产编辑器页面结构（不新增路由）：提供 Tab `2D 排布`（默认）与 `3D 派生预览`。
- `2D 排布`：
- 展示机柜的安装板平面（按 `panel` 元数据确定宽高与原点）。
- 支持从组件库拖入“元器件组件”，在 2D 面板上进行移动/旋转/对齐（单位 mm）。
- 保存的数据以 `Layout2D` 为主数据源。
- `3D 派生预览`：
- 根据 `Layout2D` 生成 3D 摆放（2D 坐标映射到 3D 变换），用于查看与钻取（只读，不提供 transform 编辑）。
- 3D 预览中仍提供碰撞提示与钻取（只读）。

- 组件库（P0）：
- 支持导入“组件”（与资产导入同源的 glb 存储链路），存到 `src/stores/component-store.ts`。
- 组件列表支持分类/搜索（P0 可先做标签字段与前端筛选）。
- 摆放体验（P0）：
- 新放置的组件默认对齐到资产工作平面（以当前编辑器约定为准）。
- 右侧面板必须能修改组件实例的 transform 与 `focusEnabled`、（P1）`collisionEnabled`。

### 3.7 初始资源创作与首启自动装载（P0，新增）

> 目标：解决“空库不可用”，首次进入即可完成“选机柜 -> 2D 排布 -> 3D 派生预览 -> 保存资产”。

#### 3.7.1 种子资源范围

- 2D 符号：12 个简单 SVG（矩形 + 文字 + 端子标记），每个组件一一对应。
- 3D 模型：12 个简单 GLB（Box/Cylinder 组合体，基础颜色材质）。
- 组件类型：至少包含 2 个 `cabinet`（用于新建资产机柜选择）+ 10 个 `part`。

#### 3.7.2 资源打包与映射

- 资源需随 `apps/demo-view` 项目交付（代码生成或静态文件均可），不依赖外部下载。
- 维护固定映射表：`componentId -> { modelResourceId, symbolResourceId, category, kind, panelMeta? }`。
- 机柜组件必须包含 `cabinetMeta.panel`（宽高/mm、原点、轴向），确保 2D 安装板可直接创建。

#### 3.7.3 首次运行初始化

- 应用启动时执行一次“种子资源引导”：
- 若检测到未初始化，则自动将 12 个 GLB 和 12 个 SVG 入库（IndexedDB）并写入组件记录（localStorage）。
- 若已初始化则跳过，避免重复入库。
- 需要版本号标记（如 `seedVersion`）支持后续升级重置策略。

#### 3.7.4 失败降级

- 任一资源初始化失败时，不阻塞页面主流程；需给出控制台告警并允许手动导入。
- 若机柜种子缺失导致无法新建资产，资产库“新建资产”入口必须提示明确原因。

### 3.8 2D 渲染技术约束（P0，新增）

- 资产编辑器 `2D 排布` 必须采用 `canvas`（或 canvas 上层库）绘制，不使用 DOM 元素块排布。
- 画布必须支持：
- 组件选中、拖拽移动、旋转显示、网格背景、选中高亮。
- 绘制 SVG 符号（来自组件映射的 `symbolResourceId`），缺失时回退矩形+文字。
- 支持从左侧组件库拖拽到画布放置。

### 3.6 场景编辑器与 v2 资产（P0）

- 场景拖入资产实例（来自资产库）后：
- 正常显示（通过 `sourceResourceId` 从 IndexedDB 异步加载）。
- 支持钻取只读查看（同 3.3）。
- 保存时仅存“资源引用 + transform + userData 覆盖”，不内联网格数据。
- 场景编辑器**不提供 2D 排布 UI**：不显示 2D Tab，不编辑 `Layout2D`；只把资产当作 3D 实例来摆放与保存。

## 4. 数据结构（建议，可直接落地）

### 4.1 `AssetRecord`（`src/stores/asset-store.ts`）

- 必含字段：
- `id`
- `name`
- `storageVersion`（用于兼容演进）
- `sourceResourceId`（指向 GLB）
- `thumbnailResourceId`
- `stats`：`{ size: {w,h,d}, tris, nodes?, meshes?, materials?, textures?, bytes? }`
- v2 新增字段（P0 建议落地）：
- `cabinetComponentId`：创建资产时选择的机柜组件 id。
- `layout2d`：安装板与元器件 2D 排布数据（单位 mm）。

### 4.2 `ComponentRecord`（`src/stores/component-store.ts`）

- 必含字段：
- `id`
- `name`
- `resourceId`（指向 GLB）
- 可选字段（P0 可先预留）：
- `tags: string[]`
- `defaultFocusEnabled: boolean`
- `defaultCollisionEnabled: boolean`
- v2 新增字段（P0 建议落地）：
- `kind?: 'cabinet' | 'part'`
- `cabinetMeta?: { panel: { widthMm: number, heightMm: number, origin: 'top-left' | 'center', axis: 'xy' | 'xz' }, thicknessMm?: number }`

### 4.3 资源存储（`src/stores/resource-store.ts`）

- 资源类型建议：
- `model/glb`
- `image/webp`（或 `image/png`）
- （P1）`model/gltf-bundle-zip`（用于保留原始输入包，便于追溯）

## 7. 验收清单（v2.0 必须全部通过）

1. 使用 `apps/demo-view/src/assets/mounted_motor_electrical_component/` 中的 `scene.gltf + scene.bin + textures/*` 作为输入，一次性选择全部相关文件导入为资产，导入成功且无白屏。
2. 导入完成后，资产库卡片可见“缩略图、名称、尺寸（W×H×D）、三角面数（tris）”，且刷新页面后仍然存在。
3. 新建资产时必须先选择机柜；未选择机柜不得进入资产编辑器，并提示原因。
4. 进入资产编辑器后默认在 `2D 排布` Tab；2D 面板尺寸与所选机柜的 `panel` 元数据一致（宽高/mm）。
5. 切换到 `3D 派生预览` Tab 后，元器件的 3D 摆放与 2D 排布一致（位置/旋转方向按映射规则一致），且 3D 预览为只读。
6. 在资产编辑器中选中某个对象，将其 `允许钻取` 开启后，`Alt+双击` 可进入钻取，只读查看生效（无法拖动/旋转编辑）。
7. 钻取状态下按 `Esc` 或点击“退出钻取”，必须完整复原：相机视角恢复、其它对象不再淡化、对象可再次正常编辑。
8. 在资产编辑器中摆放两个组件产生明显重叠，必须出现“碰撞提示”：视口高亮 + 右侧碰撞列表；点击 `定位 A/B` 能选中并镜头聚焦到对应对象。
9. 即使存在碰撞，仍允许保存资产；保存时可提示“存在碰撞但已保存”（提示不应阻塞流程）。
10. 在场景编辑器中从资产库拖入该资产实例，加载正确；场景编辑器不显示 `2D 排布` 相关 UI；场景中可用钻取只读查看并可复原。
11. 清空浏览器本地存储后首次打开应用，自动生成并入库 12 个种子组件（含机柜），无需手工导入即可新建资产。
12. 新建资产时“机柜选择”列表只展示 `kind='cabinet'` 的组件；若为空则禁止进入资产编辑器并给出提示。
13. 资产编辑器 `2D 排布` 使用 canvas 渲染：可见网格与符号，拖拽移动流畅；DOM 中不存在用于每个元器件的可视化块节点。
